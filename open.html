After the second pass, every item that was open here has been reproduced or refuted. Confirmed defects moved to Findings (sections 10–24). What remains are two documented risks:

Checked and refuted

  • A non-homogeneous relation is reported and ignored, and the computation goes on (src/echelon.c:52–60). On pq's own paths a relation can be non-homogeneous only if the previous class is already wrong; a probe build saw no case in the test suite or the SmallGroups check. Where a user hands in an arbitrary word (PqCollect, PqEchelonise), ignoring it is the right response: a relation that fails in a lower class cannot be imposed in class $c$. Only the report is weak: the message appears from InfoANUPQ level 4, and PqEchelonise returns fail.
  • One death of pq in the standard presentation check of order 64. Not a defect: pq was killed from outside. At that second the audit itself ran pkill -f ".../pq -G", which matches every pq started by GAP from that build. Six reruns of order 64 (6408 calls of PqStandardPresentation; master, correctness, master under ASan) had no failure. The first run of order 128 died the same way.
